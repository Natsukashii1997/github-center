# 网站前端照冻结方案用原生脚本与浏览器自带的动效接口，不引入 React 和动效库

规格 #1 写过“React 前端，用一个成熟的动效库实现过渡和动画”。2026-10-23 落地首页（#13）时改为：照所有者批准并冻结的视觉方案 t1b-r2（`design/t1b/`）原样采用它的共用组件脚本，用浏览器自带的 Web Animations 做过渡，服务端把数据嵌进页面。技术选型由代理负责（所有者 2026-10-23 交接时确认），本记录说明理由。

## Considered Options

- **React ＋ 动效库**（规格原写法）：要加构建步骤和第三方依赖，还要把已批准方案里的组件和动效重写一遍；重写后的外观和动效要重新核对，容易偏离批准的版本。
- **照方案的原生脚本**（采用）：方案的组件、类名和动效就是批准对象，照抄最不容易走样；页面只有几个，原生脚本足够；不新增依赖，本机直接运行。

## Consequences

- 生产组件在 `src/web/assets/gc.js`，结构和动效与 `design/t1b/app.js` 一致，只把演示数据换成真实数据、把收藏和复制换成本站接口。`design/t1b/` 本身不改，改了就要重过 T1b 并重新批准。
- 动效只动 transform 和 opacity，减少动效时由样式统一关闭；切换时的帧间隔用无头 Chrome 实测（见 `docs/design/t2-13-review.md`）。
- 服务端同理用的是 JavaScript 而不是规格写的 TypeScript，沿用此前各单的做法。
- 以后页面变多、交互变复杂到原生脚本难以维护时，再重新讨论。
