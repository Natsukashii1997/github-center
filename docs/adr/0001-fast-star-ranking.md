# 涨星榜用“全站事件找候选＋官方核数”快速出榜，不做逐日全站完整性证明

原方案为了数学上证明全站一个不漏，每天要读约 6.6 万个仓库，需要十几个小时，用户明确不接受这种慢。2026-10-23 决定改为：用全站公开事件数据（GH Archive 一系）和 GitHub 官方热门榜找候选，再用 GitHub 官方 Star 数据核对候选的真实涨星数后排名。排序不经人挑选，页面上的数字都来自官方，每天很快出榜。代价是不能证明一个不漏。

## Considered Options

- **逐日严格证明**（原方案）：能证明完整，但太慢；改作校准用的标准答案，由 Codex 维护。
- **只用官方热门榜**：最快，但每次只有二十几个项目，排序规则不透明，也不是纯涨星。
- **直接用事件计数排名**：不可行。2026-10-23 实测，公开事件库只记录到真实 Star 的约 1—2%（例：morluto/rea 在 10-12—10-18 记到 3,317 次，实际约 +22 万）；排序仍有参考价值，上周前 10 名与一份第三方多源周榜重合 8 个。

## Consequences

- 事件数据只用来找候选，绝不把事件计数当涨星数展示。
- 可能漏掉在事件数据里被严重漏记的项目，所以用两种方式兜底：严格方案每产出一天结果，就和快速方法同一天的前 20 名（含并列）对照，名单和数字都一致才算过关；每天出榜时自检，不达标就在当天榜单上标注“可能不完整”。
- 依赖免费的第三方公共数据。数据源中断时当天按更新失败处理，保留上次结果和真实日期。
