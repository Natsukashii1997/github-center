# 周报交接：给猛鬼兽（Hermes）

周报 = 本周 GitHub 涨星前 10（涨星榜「近 7 天」窗口，末位并列一起列出）。本仓库只生成文字，不发送；发送由猛鬼兽负责（#28，需求见 `docs/product/requirements-regrill.md` 末尾「日报改周报」）。

## 什么时候发、发给谁

- 每周一 11:30（Asia/Shanghai），发到所有者本人的飞书私聊。只发这一处，不发群聊。
- 本仓库的每日定时任务（`scripts/schedule.sh` 装的 launchd 任务 `cn.github-center.update`）在设置页设的时间（默认北京时间 10:00；2026-11-03 起可在设置页改，最早 09:00）起跑 `npm run update`：出榜、全站 Star 前 100、历史榜（Skill 安装量）、热点榜、精选榜、补资料、归类，然后 `npm run weekly` 写出当天的周报文件。平时 15 分钟左右跑完，默认时间下 11:30 前已就绪（设置页把更新时间改到 11:15 以后，11:30 推送前就不一定就绪）；日志 `data/logs/update.log`，最后一行是 `exit N`。

## 格式

飞书能直接渲染的 Markdown，原样作为一条消息发出即可，不要改写、不要摘要：

- 标题：`## GitHub 本周涨星前 10 · 10 月 17 日–10 月 23 日`（近 7 天区间）
- 一行说明数据截至哪个统计日、什么时候生成
- 有问题时有一段 **提示**（不是最新数据、可能不完整、更新失败），照发
- 前 10 每项两行：`**名次. [作者/仓库](本机项目页)**（并列）　近 7 天 +新增　总 Star 数　[GitHub](链接)`，下一行一句话简介（还没生成时写「简介生成中。」）
- 末尾一行数据来源说明。本机项目页链接只在运行本中心的电脑上能打开，手机上点 GitHub 链接。

## 卡片

`<统计日>.card.json` 原样作为 `msg_type: interactive` 的消息内容发出，不要改写。约定：

- 横幅图不在文件里。发送方用自己的飞书身份上传一张固定横幅（`image_type: message`），把下面这个元素插在 `body.elements` 最前面：`{"tag": "img", "img_key": "<上传得到的 key>", "alt": {"tag": "plain_text", "content": "本周 GitHub 涨星榜"}, "scale_type": "crop_center", "preview": false, "corner_radius": "8px"}`。没有横幅就不插，卡片照样能发。
- 前 3 名是灰底整行，4 名以后三列；整行点开 GitHub。底部三个按钮：GitHub 周趋势、完整涨星榜（电脑）、我的收藏（电脑）。
- 2026-11-05 实发核对过：飞书卡片 JSON 2.0 的 `column_set` 不认 `padding` 和 `behaviors`，整行跳转要用 `action.multi_url`。
- 仓库名、一句话、提示里会被当成格式的字符（`* _ ~ [ ] < > & 反引号`）已按飞书官方「富文本（Markdown）组件」的转义写法换成 `&#实体编号;`，发送方不用再处理。
- 和 Markdown 一样只写一次、已有不重写。最新一期有周报但缺卡片文件（比如中途断掉）时，跑一次 `npm run weekly` 会照周报补上；更早的统计日不补。
- 取最新一份卡片：同上，按文件名取最新的统计日，再读同名的 `.card.json`。有 `.feishu.md` 而卡片缺失、为空或读不出来时，按下面「先检查再发」只发一句说明，不发旧卡片。

## 先检查再发

周一 11:30 时，最新一份的统计日应当是**昨天（周日）**。

- **找不到任何文件**，或**最新一份的统计日早于昨天**：不要发旧内容，也不要自己编榜单。只发一句简短说明，例如：「本周周报没有生成：最新数据停在 10 月 23 日，榜单可能没更新。」把最新一份的日期写上（没有文件就写没有）。
- **文件存在但为空或读不出来**：同上，发一句说明，不发内容。
- 文件里自带「提示」时照常发送，提示原样保留，不删。

## 不要做的事

- 不改写数字、不补数据、不加没有依据的原因。卡片里的数字和文字也一样。
- 不把内容发到群聊或其他机器人。
- 本仓库不提供也不需要任何 token；发送用猛鬼兽自己的飞书身份。
