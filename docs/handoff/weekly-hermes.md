# 周报交接：给猛鬼兽（Hermes）

周报 = 本周 GitHub 涨星前 10（涨星榜「近 7 天」窗口，末位并列一起列出）。本仓库只生成文字，不发送；发送由猛鬼兽负责（#28，需求见 `docs/product/requirements-regrill.md` 末尾「日报改周报」）。

## 什么时候发、发给谁

- 每周一 11:30（Asia/Shanghai），发到所有者本人的飞书私聊。只发这一处，不发群聊。
- 本仓库的每日定时任务在北京时间 10:00 起跑：出榜、补资料、归类，然后跑 `npm run weekly` 写出当天的周报文件，11:30 前已就绪。
  （定时脚本正在另行重写；`npm run weekly` 这一步要在重写时加进去，见 #28 PR 说明。）

## 格式

飞书能直接渲染的 Markdown，原样作为一条消息发出即可，不要改写、不要摘要：

- 标题：`## GitHub 本周涨星前 10 · 10 月 17 日–10 月 23 日`（近 7 天区间）
- 一行说明数据截至哪个统计日、什么时候生成
- 有问题时有一段 **提示**（不是最新数据、可能不完整、更新失败），照发
- 前 10 每项两行：`**名次. [作者/仓库](本机项目页)**（并列）　近 7 天 +新增　总 Star 数　[GitHub](链接)`，下一行一句话简介（还没生成时写「简介生成中。」）
- 末尾一行数据来源说明。本机项目页链接只在运行本中心的电脑上能打开，手机上点 GitHub 链接。

## 先检查再发

周一 11:30 时，最新一份的统计日应当是**昨天（周日）**。

- **找不到任何文件**，或**最新一份的统计日早于昨天**：不要发旧内容，也不要自己编榜单。只发一句简短说明，例如：「本周周报没有生成：最新数据停在 10 月 23 日，榜单可能没更新。」把最新一份的日期写上（没有文件就写没有）。
- **文件存在但为空或读不出来**：同上，发一句说明，不发内容。
- 文件里自带「提示」时照常发送，提示原样保留，不删。

## 不要做的事

- 不改写数字、不补数据、不加没有依据的原因。
- 不把内容发到群聊或其他机器人。
- 本仓库不提供也不需要任何 token；发送用猛鬼兽自己的飞书身份。
