## 目标、用户与边界

- 私人GitHub快速中心：每天约5—10分钟掌握值得关注的项目变化，发现值得进一步了解和使用的工具。
- 以GitHub项目为中心，覆盖公开项目；外部报道是项目补充，不扩成独立泛AI新闻站。
- 先本人使用、登录后访问；常浩是管理员。未来邀请小团队成员共同浏览同一信息库，各自保留私人收藏，不做共享评审、试用派单或采用审批。
- 网站以电脑使用为主，兼顾手机浏览。现有电脑运行是当前验证基线；最终安全访问与跨设备方案尚未选定，不能据此擅自开放公网端口。
- AIHOT是明确主参考：整体阅读风格、信息组织、后台采集与生成思路。未批准精确视觉稿，也未锁定照搬其全部技术栈。

## 首版功能与规则

| 编号 | 功能 | 已确认含义 |
|---|---|---|
| R01 | 官方热门 | GitHub Trending日／周／月榜，保留官方排名；与纯涨星榜分开展示 |
| R02 | 全站涨星榜 | 近1／7／30个GitHub官方统计日，每日更新；按期间新增数量排序，增长百分比为辅助信息；首版每个涨星榜Top20含末位并列 |
| R03 | 累计高星榜 | 当前累计Star最多的项目，独立入口，不能与期间增长混为一谈 |
| R04 | 新项目发现 | 最近创建且值得了解的项目，作为第四个独立入口；“最近”的具体天数和排序规则尚未定案 |
| R05 | 分类筛选 | AI应用工具、Agent／MCP、工作流自动化、知识管理与办公效率、Skill；同时保留全部领域。分类是浏览筛选，不是全站采集的白名单 |
| R06 | 更新与连续排名 | 每天更新一次并显示实际更新时间；一直第一就一直第一，不因看过而隐藏或为新鲜感轮换。失败时保留上次结果及真实日期 |
| R07 | 中文列表与详情 | 列表有一句话用途、分类、排名和Star信息；详情解释解决什么问题、适合谁、具体使用例子、环境或账号条件及原始文档。未经实测的效果不写成已验证 |
| R08 | 仓库与具体Skill | 榜单以仓库为单位；详情能选择仓库内具体Skill，复制其对应安装任务；可收藏整个仓库或一个具体Skill |
| R09 | 收藏与账号 | 只保留一个“自己感兴趣”的收藏能力，不另设关注；跟个人账号同步，换电脑或浏览器可找回，未来成员各自拥有私人收藏 |
| R10 | 一键复制安装任务 | 点击复制可发给Agent的完整安装指令，默认在该Agent所在电脑安装、配置、验证可调用并说明使用方式；服务器项目或在线服务给符合项目实际的操作指令；缺账号、密钥或涉及付费时说明缺项，不自行扩大授权 |
| R11 | 历史榜单 | 首版需要按日期回看实际保存的榜单；缺失日期如实显示，不能用今日数据伪造过去榜单 |
| R12 | AI日报 | 首版需要；基于当天四类榜单及可用历史变化生成中文概览和重点项目介绍，同仓跨榜合并，保留来源；有历史才判断新上榜、持续热门或加速；有证据才说明热度原因 |
| R13 | 多项目对比 | 首版需要；并排比较用途、功能、使用条件、维护情况、Star信息，未知项明确标记。选择数量上限等交互细节尚未定案 |
| R14 | 私人访问与未来团队 | 首版登录后本人使用，后续按邀请开放；共同浏览，各自收藏。具体认证方式与团队实施时间尚未确定 |

Top20含并列首先约束涨星榜；其他入口的数量和分页尚未明确，不能自动套同一个20条上限。

## 明确取舍及被覆盖的旧建议

- “24小时／7天／30天”后来由用户明确收敛为“近1／7／30个官方统计日”；不是北京时间自然日或滚动24小时承诺。
- Q11曾建议局部收录池，用户明确纠正为全站；不能退回收藏池、精选池、仅Trending或固定高星池来声称完成全站要求。
- Q12选每天更新一次，不采用原建议每6小时更新。
- 连续霸榜持续展示，不采用原建议在精选中自动隐藏已看热门。
- 收藏与关注曾建议分开，用户明确只要收藏；复杂标签、笔记、评论、评分、未读筛选都不是默认首版必需功能。
- 单项目增长曲线移出首版；历史回看、AI日报、多项目对比均为首版范围，不能再次移到后续而不说明范围变化。
- 团队选“共同浏览，各自收藏”，不是共同评审、分派试用或共享采用流程。
- 尽量零新增费用，撤销“每月100元”的助手建议；未授权购买API、credits、付费数据或托管资源。

## 数据与运行要求

全站是产品目标，不是已经完成的覆盖证明。现有实验围绕GitHub搜索索引可见的公开仓库（含fork），采用全量分片分页、固定窗口计分、两轮候选搜索、最终新鲜复核和Top20含并列；缺项保持未知，不补零，不跳过。

目前采用的指标为“对应日桶内创建、采集时仍有效的Star”，不是精确净增或完整新增流水。官方统计日可以按桶键计算，但精确UTC映射和最新一日已经结束的证明未通过；当前boundary_mode=observed_utc_mapping、completed_day_verified=false。历史记录可因取消Star变化；正式历史榜单需要保存当时发布的不可变版本。

每天更新的实际容量、跨日缓存与零新增费用的可持续性仍待验证。用户已授权先完成有限数据实验，再推进规格和产品实现；详细运行边界见HANDOFF.md及原实验CURRENT.md。

## 功能串联及最终用户路径

每日采集与验证 → 更新四类榜单并保存历史 → 根据同批事实生成AI日报 → 浏览列表与项目详情 → 对比候选 → 收藏仓库／具体Skill，或复制对应安装任务交给Agent。

首版真实验收路径：登录 → 浏览当日榜单或日报 → 看懂用途和条件 → 对比 → 收藏并在另一浏览器／设备找回 → 复制正确安装任务；另验历史回看、缺失记录、更新失败与旧日期展示。页面、模拟数据和单次脚本成功均不能单独代替此验收。

## 仍待规格化，不应替用户猜定

- 新项目窗口与排序、辅助增长百分比的基准及零分母处理。
- 各入口分页、详情字段优先级、对比上限、Skill目录识别和独立标识。
- 登录、安全访问、跨设备同步、邀请权限的具体方案。
- 首次无历史、上游失效、日报生成失败时的具体界面文案与状态。
- AIHOT风格的精确视觉对象、版本及用户批准；正式Spec、Ticket和验收切片。

技术细节由接手代理主动完成；只有改变目标、首版范围、成本、权限或业务验收的取舍才集中询问用户。
