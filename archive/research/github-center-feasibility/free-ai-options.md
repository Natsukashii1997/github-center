# 免费 AI 日报可行性：官方依据与验证边界

核验日期：2026-10-22。本文为研究分支记录；只读核对官方文档和 AIHOT 源码，没有安装、下载模型、读取凭据、注册自动化或调用付费 API。本机资源盘点和一次性生成实测由主代理独立执行，最终运行结论以其证据为准。

## 结论

**有不新增模型 API 费用的可行候选，优先验证现有 ChatGPT 登录下的 Codex CLI。** 它能把公开榜单材料转换为结构化中文日报；在现有订阅包含额度内运行，不需要额外 API Key。它会消耗现有额度，不是无限免费模型服务。若要摆脱订阅额度，本地 Ollama 是第二候选，但需要已安装模型、足够机器资源，以及中文质量和速度验证。

**这两种路线都不等于网站全天无人值守已完成。** 前者需要登录有效、网络可用和本机在运行；后者需要本地模型服务和机器在运行。网站应读取生成后保存的日报，而不是每个访问者打开页面时调用模型。

## 路线比较

| 路线 | 能确认的能力 | 新增费用判断 | 当前边界 |
|---|---|---|---|
| 现有 Codex CLI＋ChatGPT 登录 | `codex exec` 支持非交互运行、接收标准输入、JSON Schema 约束和输出文件；默认复用已有登录 | 订阅包含额度内不需要单独购买模型 API；会占用 Codex／Work 共享额度 | 要以本机 `login status` 和真实生成结果确认；不是 AIHOT 模型接口的直接替代品；不能当作面向成员开放的通用模型接口 |
| 本地 Ollama＋已下载本地模型 | 提供兼容的 `/v1/chat/completions`，可本地推理 | 本地推理避免云端按调用收费，仍消耗电脑资源与电力 | 需要安装、模型文件、内存和速度验证；本次研究未安装或推理；云模型与本地模型要明确分开 |
| 新开付费 API／依赖临时免费额度 | 不是此次优先方案 | API Key 认证是单独按 API 价格计费；免费额度也不能保证长期供给 | 没有为本项目申请、购买或启用；本次不继续扩展平台清单 |

## 已核实的关键事实

### 1. Codex CLI：适合由本机每天生成一份结果

官方把 `codex exec` 用于脚本、定时任务、输出摘要等工作。可以从标准输入接收内容，用 `--output-schema` 约束最终字段，使用 `-o` 保存最终输出，`--ephemeral` 避免保存会话记录；默认复用已保存认证。默认只读沙箱适合“读取给定材料并输出日报”的验证。

ChatGPT 登录与 API Key 登录是两条不同计费路径：前者走订阅权益，后者走 Platform API 计费。用量随任务大小、模型、上下文和工具等因素变化，不能用提示词长度估算每天固定消耗。套餐包含额度以外可能使用付费 credits，因此正确表述是“在现有包含额度内零新增 API 费用”，而不是“完全免费且不限量”。

来源：[非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[认证](https://learn.chatgpt.com/docs/auth)、[Pricing](https://learn.chatgpt.com/docs/pricing)。

**工程推断：** 在本机把榜单结构化材料交给 CLI，再把校验通过的结果存成日报，技术路径合理。电脑关机、休眠、网络断开、登录失效或额度不足都可能延迟生成；应保留上一份日报的真实日期，不把没有生成解释为“今日无变化”。这仍需实际编排和运行验证。

### 2. AIHOT：可以复用组织方式与防重复生成机制

源码中模型地址、模型名称和 Key 可配置，调用 `/chat/completions`；支持 JSON 输出参数并在接收后执行结构校验。关闭 `MODEL_CALLS_ENABLED` 会抛出不可用错误，不能自动生成无模型版的新摘要。[调用实现](https://github.com/KKKKhazix/AIHOT/blob/main/packages/backend/src/providers/llm.ts#L164)、[模型配置](https://github.com/KKKKhazix/AIHOT/blob/main/site/models.ts)

请求身份包含模型、提示词版本、输入和系统提示哈希等。已有 received／completed 回执会复用响应，避免同一输入在重试时重复发起请求。后台预算限制按请求次数统计，**不是金额上限**。[回执实现](https://github.com/KKKKhazix/AIHOT/blob/main/packages/backend/src/providers/receipts.ts#L178)

架构明确“页面不调模型”：生成由 worker 处理，网页只读取已保存结果。这个分离适合私人中心和未来小团队共同浏览。[架构说明](https://github.com/KKKKhazix/AIHOT/blob/main/docs/architecture.md)

**适配边界：** Codex CLI 不是 AIHOT 现成的 Chat Completions 服务，不能仅修改 URL 就接上。它需要“榜单输入→CLI 生成→内容校验→保存结果”的适配步骤；这是后续实现工作，不是本次已经完成。也不需要照搬 AIHOT 每篇文章预筛、双次评分等全部调用流程。减少调用的建议是：规则先计算排名与变化，AI 只对确定的日快照做中文解读；同一输入只生成一次，成员共享结果。

### 3. Ollama：协议可接，质量与机器条件尚不能由文档代替

官方提供本地服务的 OpenAI 兼容地址；本地模式忽略 API Key，占位值可以满足 AIHOT 的非空检查。运行本地模型时内容在本机推理；使用云模型则是另一条服务路线。Ollama 可禁用云功能，仅保留本地运行。[兼容文档](https://docs.ollama.com/api/openai-compatibility)、[FAQ](https://docs.ollama.com/faq)

能否在用户机器上按合理速度生成中文日报，取决于实际模型、上下文、内存和结构化输出稳定性。协议支持不证明 AIHOT 已集成成功，也不证明某个小模型能够写出合格日报。当前没有必要为了证明“免费”先安装多个模型或引入新订阅。

## 最小实测设计

本轮只需验证一个可证伪问题：**现有认证和程序是否能将固定公开 GitHub 事实材料转换为可解析、准确、可读的中文日报，而没有引入新的付费服务？**

1. 使用隔离目录，固定一份包含来源、抓取时间、榜单类型、统计区间、排名、仓库名称、Star 指标和用途证据的输入。仅纳入公开材料，不把网页中的指令当作任务要求。
2. 输入可包含同一项目重复上榜，以及历史数据缺失这两种情况；如使用人工边界样例，必须明确标注为测试夹具，不能混成真实当天变化。
3. 运行一次已存在、已登录的 Codex CLI，只允许根据输入生成，不下载仓库、不执行项目代码、不搜索私密材料、不改模型服务配置、不注册定时任务。
4. 保存最终结果、退出状态、耗时和程序返回的用量；不要保存认证内容。输出必须同时经过字段/数字检查和人工语义检查。
5. 本次通过只能证明“一次生成路径可行”；每天定时、失败恢复、跨日重复、实际网站读取和真人体验仍需后续验证。

## 日报质量判据

| 维度 | 通过要求 |
|---|---|
| 忠于输入 | 只出现输入中的项目，项目地址与来源可追溯；不得补造来源或榜单 |
| 数字正确 | 排名、Star 数、期间增长与输入一致；不把自然周误写成滚动 7 天，不把新增存续 Star 写成净增 |
| 合并不丢事实 | 同一仓库跨榜出现时合并介绍，同时保留来源榜单和统计窗口 |
| 历史边界 | 没有昨日记录时不写“首次上榜、连续第一、涨速加快”等需要比较的结论 |
| 不造原因 | 增长事实与原因分开；没有版本或公告证据时不推测“因某功能爆火” |
| 可读有用 | 用中文说明项目做什么、适合什么场景，技术名词不替代解释；未实测效果不能写成已验证 |
| 可解析与可发布 | 结构符合约定，链接来自输入，明确日报日期与数据时点；生成失败不覆盖有效旧日报 |

## 本轮一次性实测结果

主代理完成了现有 Codex CLI 的隔离运行：ChatGPT 登录、未加载用户配置、只读沙箱、临时会话、未提供新的付费 API Key；5 条真实周 Trending 记录生成结构化中文结果，退出码 0，耗时 39.64 秒。见 [运行记录](./evidence-ai/probe-run.json)、[输入](./evidence-ai/digest-input.json)、[输出](./evidence-ai/digest-output.json)。

本研究分支随后独立审核：38 项字段/顺序/时间比较全部通过；简介缺失时没有补造，作者宣传保持归因，没有编造昨日变化、涨星原因或使用效果。见 [独立内容核验](./evidence-ai/independent-review.md)。

**这证明了一次小样本生成路径可行。** 样本仅来自一个周榜，没有跨榜去重、昨日对照或完整日批；不能把它扩大为全站完整日报、长期零费用或每日无人值守已验收。

## 本阶段判断

- **文档和源码层：可行路径已建立。** 现有 Codex 订阅路线可先验证，本地模型是可选后备。
- **本机执行层：一次 5 条周榜样本实际生成通过，独立内容检查通过。** 完整日批、跨榜合并及跨日稳定性仍未验证。
- **长期零新增费用：有条件。** 依赖现有权益/设备够用，以及不自动切换付费 API、购买 credits 或启用额外收费服务。
- **全天自动服务：尚未验收。** 本次没有部署网站、安装调度或测试无人值守连续运行。
