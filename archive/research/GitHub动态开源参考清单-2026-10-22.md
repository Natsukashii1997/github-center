# GitHub 动态门户：49 个开源源码参考与补充候选

核验日期：2026-10-22（北京时间）。用途：为未来自建 GitHub 项目动态入口收集参考，不是部署、安装或最终选型结论。

这份清单保留用户的最新基线：GitHub 官方已经有 Trending 日/周/月榜，累计总星可由官方搜索排序获得。自建产品需要参考的是官方之上的增量：中文理解、历史回看、真实增长、项目对比、收藏与持续跟踪。

## 先确认现成基线

- [GitHub Trending](https://github.com/trending)：日榜、周榜、月榜与语言筛选。
- [GitHub 累计 Star 排名](https://github.com/search?q=stars%3A%3E10000&type=repositories&s=stars&o=desc)：官方搜索按 Most stars 排序。
- 本轮实际浏览器观察：Trending 周榜显示期间新增星数，但列表顺序不是严格按该数字降序。
- “过去一周新建的高星仓库”“过去一周更新过的高星仓库”“过去一周新增星最多”“增星百分比最高”“综合趋势分最高”是不同榜单，应分列、分名。

## 结果与核验边界

- **49 个独立、许可证明确、包含实现代码的开源参考**：19 个完整产品/前台，7 个趋势分析，5 个采集/API，8 个历史/订阅，3 个个人跟踪，7 个数据底座。
- 另列 **12 个许可信息不完整、冲突或受限的源码参考**，不计入上述开源数量。
- 数据归档、内容精选、只有产品介绍的仓库另列，不冒充完整应用源码。
- 核验读取了 GitHub 第一方仓库、README、目录、许可证/API 元数据，重点候选补读了计算源码。**未安装、未运行、未做安全准入或部署验收**。README 的功能声明与运行效果仍有距离。
- 下表“最近推送”为本轮 GitHub API 的 pushed_at UTC 日期。自动数据提交也会更新它，因此它不等于代码最近维护日期。49 项本轮元数据均未归档。
- 不因低 Star 排除有用实现；低 Star、新仓库只表示成熟度证据不足，不能把其功能清单当成稳定性证明。

## 后续自己做时，最值得带走的四条设计判断

1. **官方榜作为发现入口，自己的快照作为增长证据。** 两者保留独立字段，不混为一个“热度”。
2. **先公开统计范围。** “全GitHub”“≥1万Star”“上过Trending”“个人关注池”成本和覆盖不同，不能用局部数据标成全站榜。
3. **空白、缺测、零增长、掉星、增速下降分别显示。** 首次入库没有基线，不应把全部历史星数计入今天增长；当期抓取失败不推进成功日期。
4. **先按产品增量选参考。** 中文门户看 Ibook000；真实增长看 RepoTempo/Trending Repos/RepoPulse；总榜/详情看 Star History/Gitstar Ranking；订阅看 isboyjc/RSSHub/Agents Radar。是否采用某个技术栈，留到真正启动实现时决定。
