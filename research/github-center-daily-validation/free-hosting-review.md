# 免费每日采集托管：GitHub Actions 独立核验

核验日期：2026-10-22。只读检查 5 个 GitHub 官方页面，没有查看账户套餐、账单、凭据或 Secret，没有创建仓库、发布代码、修改设置或注册任务。

**结论：GitHub Actions 是现实的免费候选，但“私人仓库＋每天长时间采集”不能直接认为免费。公开采集仓库的标准 runner 可免运行分钟费；这需要用户接受公开采集代码与公开结果，尚未获得授权，也尚未完成实际云端运行验证。**

## 已确认的官方规则

| 对象 | 当前规则 | 对本项目的影响 |
|---|---|---|
| 公开仓库 | 标准 GitHub 托管 runner 的使用时间免费；较大型 runner 始终收费 | 可考虑只公开通用采集器和 GitHub 公开统计，不必把私人中心、收藏、用户信息一起公开 |
| 私有仓库 | 按账户套餐提供免费分钟；超出部分可能收费 | GitHub Free 每月 2,000 分钟，Pro／Team 每月 3,000 分钟；与账户其他运行共享，未核实当前余额 |
| 存储 | 免费分钟不等于无限存储；Free 的 artifact／Packages 共用 500 MB，缓存另有每仓 10 GB 额度 | 需压缩结果、限制保留期，并验证当前预算设置；不能囤积每日全部原始响应后仍宣称永久免费 |
| 超额控制 | 无有效支付方式时，额度用尽后停止；有支付方式时需要预算及“达到预算停止使用”设置控制超额 | 本轮没有检查或修改用户账户设置，不能保证当前账户已防止收费 |

来源：[Actions 计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)、[各套餐包含额度](https://docs.github.com/en/billing/reference/product-usage-included)。

运行方面，GitHub 托管 runner 的单个 job 最长 **6 小时**，到时会终止失败。因此超过 6 小时的采集要拆为可续接的有限批次，保存断点，并遵守同一 API 配额；拆 job 不增加 API 额度。[官方运行限制](https://docs.github.com/en/actions/reference/limits)

定时任务可能延迟，负载很高时可能丢弃排队任务；应避开整点，并保留补跑与完成检测。公开仓库连续 60 天无活动会自动停用定时工作流，不能把成功创建 schedule 当作长期无人维护保障。[官方 schedule 说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## API 额度不会因为上云自动变大

Actions 内置 `GITHUB_TOKEN` 通常只有 **每仓库每小时 1,000 次** REST 请求。个人认证通常为每小时 5,000 次，并与同一用户其他相关调用共享；不是换一个 token 就增加一份额度。[官方 REST 限额](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

所以，不能把本机现有 5,000／小时的测量结果直接套到默认 Actions 工作流。若每日有 30,000 次消耗 primary 额度的读取，内置 token 就需要约 30 个小时额度，已经超过一天；这只是容量算术，尚未计重试，也不代表实际请求数一定是 30,000。条件请求命中率、动态候选缩小效果，应以实际测量为准。

将个人认证或 GitHub App 用于云端是另一个配置与权限动作。当前 Mac 的登录可用，不代表已授权把本地登录资料上传为 Actions Secret。本轮没有读取、复制或上传任何认证材料，也不建议开多个账户或仓库规避限额。

## 对免费路线的判断

| 候选路线 | 当前判断 | 必须补齐的证据 |
|---|---|---|
| 现有 Mac 本地采集 | 继续作为当前默认验证环境；无新增云分钟费 | 全批耗时、当天在线时长、睡眠／离线补跑、连续数日完成记录 |
| 私有仓库＋标准托管 runner | 小批适合；数小时／日的任务不能依赖基础免费分钟 | 实际套餐与剩余额度、月度总分钟、存储和超额停止设置 |
| 公开采集仓库＋标准托管 runner | 可成为不依赖电脑在线的免费候选 | 用户批准公开对象与范围，API 认证方式，分批续跑，全批容量，调度失败与存储保留验证 |

仅作尺度参考：2,000 分钟平均到 30 天约为每天 67 分钟；3,000 分钟约为每天 100 分钟。如果任务每天运行 8 小时，则每月约 14,400 分钟，明显超出两者。以上是规划测算，不是本次实际云端耗时。

建议先用根任务正在做的实测确定每日请求量和耗时。若现有电脑能在可接受在线时段完成，保留本地方案；若明显需要整日在线，再把“公开通用采集层、私人中心读取成品”作为一个具体选项交由用户决定。**本报告不表示用户已经选择公开仓库，也不表示云端日更已部署或已验收。**
