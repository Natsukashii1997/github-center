## 会记录什么

- 实际开始、完成、总耗时、延迟；限流等待单独记录，不能把多个工人累计等待说成墙钟时间。
- 全量候选枚举、每项评分、末位门槛与并列、第二轮候选复核及未解决项。
- 每次真实 HTTP 200/304、条件请求、跨执行日缓存命中；同批次断点复用单列。
- 一次真实进程中断后的恢复。未真实发生的电脑休眠或断网不声称验证通过。
- 不可变原始响应及评分来源，保留首次失败，不把未知当零。

初始候选门槛为总星 1,013，只是由旧样本提出的探索下界。本次所有候选和历史数据重新读取；最终第 20 名必须新鲜复核并支撑排除范围，否则自动扩展候选，不能只改榜单。

## 运行与权限

使用本机现有 Python、GitHub CLI 及其现有登录；保守限制本任务每滚动小时最多 4,000 个非 304 核心请求，并根据服务端剩余额度退让，尽量为其他用途保留 1,000 个请求。现有账号其他程序的使用不能完全由本任务控制。

电脑开机并联网时才可采集；不修改系统休眠、电源或网络设置。中断后从本批已保存部分继续。账户鉴权失败、持续异常或需要新增权限/费用时停止并说明。

所有输出只存放在本隔离目录，未建公开仓库、未上传数据或凭据、未接入付费服务。

## 查看结果

- `CURRENT.md`：人可读的当前状态与下一步。
- `status.json`：工作进程定期保存的进度；时间不更新时需结合进程状态判断，不能只看旧文件。
- `results/各批次/榜单.md`：对应批次真正通过完整性检查后才生成。
- `results/各批次/result.json`：完成时的耗时、缓存、候选范围和证据索引。
- `recovery-check.json`：真实中断补跑核对结果。
- `acceptance-review.md`：通过、不通过与证据边界。

本次跟踪留在当前会话。仅在冷启动完成、明确故障或最终验证结果出现时通知；无变化时保持安静。自动化注册或进程启动都不等于采集完成。

如需人工停止，在本目录创建名为 `STOP` 的文件；程序会在新请求/等待检查点停止，正在进行的单次网络请求可能最多等待 90 秒返回。恢复前须先查明停止原因，不得直接抹掉失败记录。
